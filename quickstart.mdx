Get Faramesh running and see governance in action in under 5 minutes.

<Steps>

<Step title="Install Faramesh">

Choose your preferred installation method:

<CodeGroup>

```bash Homebrew (macOS/Linux)
brew install faramesh/tap/faramesh
```

```bash Install Script
curl -fsSL https://raw.githubusercontent.com/faramesh/faramesh-core/main/install.sh | sh
```

```bash Docker
docker pull ghcr.io/faramesh/faramesh:latest
```

```bash Go
go install github.com/faramesh/faramesh-core/cmd/faramesh@latest
```

```bash Python SDK
pip install faramesh
```

</CodeGroup>

Verify the installation:

```bash
faramesh --version
```

</Step>

<Step title="Run the Demo">

See Faramesh in action with a synthetic agent:

```bash
faramesh demo
```

<Step title="Govern Your First Tool">

Add governance to a Python function in under 60 seconds:

```python
from faramesh import govern

def stripe_refund(amount: float, currency: str) -> str:
    """Refund a charge via Stripe."""
    # Your Stripe API call here
    return f"Refunded {amount} {currency}"

# Wrap with govern() - preserves type hints and docstrings
governed_refund = govern(
    stripe_refund, 
    policy='payment.yaml', 
    agent_id='payment-bot'
)

# Use it like the original function
try:
    result = governed_refund(amount=100, currency='usd')
    print(result)  # "Refunded 100 usd"
except DenyError as e:
    print(f"DENY: {e.reason}")
except DeferredError as e:
    print(f"DEFER: approve with: faramesh agent approve {e.defer_token}")
```

<Info>
The `govern()` decorator auto-starts the faramesh daemon on first call. No separate setup in development.
</Info>

</Step>

<Step title="Create Your First Policy">

Create `payment.yaml` with governance rules:

```yaml payment.yaml
faramesh-version: '1.0'
agent-id: payment-bot
default_effect: permit

vars:
  max_refund: 500

rules:
  # Deny destructive shell commands
  - id: deny-destructive-shell
    match:
      tool: shell/run
      when: 'args["cmd"] matches "rm\\s+-[rf]"'
    effect: deny
    reason: destructive shell command blocked by policy
    reason_code: DESTRUCTIVE_SHELL_COMMAND

  # Require human approval for high-value refunds
  - id: defer-high-value-refund
    match:
      tool: stripe/refund
      when: 'args["amount"] > vars["max_refund"]'
    effect: defer
    reason: refund exceeds threshold — requires finance approval
    reason_code: HIGH_VALUE_REFUND

  # Deny mass email
  - id: deny-mass-email
    match:
      tool: send_email
      when: 'len(args["recipients"]) > 50'
    effect: deny
    reason: mass email to >50 recipients requires manual review
    reason_code: MASS_EMAIL_LIMIT
```

Validate your policy:

```bash
faramesh policy validate payment.yaml
```

</Step>

<Step title="Start the Daemon (Production)">

For production deployments, run the daemon as a service:

```bash
faramesh serve --policy payment.yaml
```

The daemon:
- Loads and compiles the policy
- Opens the WAL (write-ahead log)
- Initializes the DPR (Decision-Provenance Record) chain
- Starts accepting connections on `/tmp/faramesh.sock`

<Tip>
Use `faramesh init` to auto-detect your environment and generate appropriate configs (Kubernetes, Lambda, Docker, etc.)
</Tip>

</Step>

</Steps>

## Understanding the Three Decision Modes

<CardGroup cols={3}>
  <Card title="PERMIT" icon="check" color="#10b981">
    Action is allowed and executes immediately
  </Card>
  <Card title="DENY" icon="ban" color="#ef4444">
    Action is blocked before execution
  </Card>
  <Card title="DEFER" icon="clock" color="#f59e0b">
    Execution pauses until human approves/denies
  </Card>
</CardGroup>

## What Just Happened?

1. **Policy Compilation**: The YAML policy was parsed and expr-lang conditions compiled to bytecode (~1μs per rule)
2. **Governance Pipeline**: Each tool call went through an 11-step evaluation pipeline
3. **WAL-First Audit**: Every decision was written to disk BEFORE being returned (tamper-evident)
4. **DPR Chain**: All decisions recorded in a cryptographic chain with SHA256 hashes
