The Faramesh daemon (`faramesh serve`) is a long-running process that loads your policy, opens the WAL and DPR store, and accepts governance requests via a Unix domain socket.

## Architecture

```
┌──────────────────────────────────────────────────────────────┐
│  Agent Process (Python, Node, Go)                           │
│                                                              │
│  governed_tool = govern(fn, policy='policy.yaml')           │
│  governed_tool(args)  ──┐                                   │
└─────────────────────────┼───────────────────────────────────┘
                          │ JSON over Unix socket
                          │ /tmp/faramesh.sock
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  Faramesh Daemon                                             │
│                                                              │
│  1. Load policy YAML + compile expr conditions              │
│  2. Open WAL + DPR SQLite store                             │
│  3. Listen on Unix socket                                   │
│  4. Evaluate: Pipeline → WAL → Decision                     │
│  5. Return: PERMIT | DENY | DEFER | SHADOW                  │
└──────────────────────────────────────────────────────────────┘
```

## Starting the Daemon

### Basic Usage

```bash
faramesh serve --policy policy.yaml
```

The daemon:
- Loads and compiles `policy.yaml`
- Creates WAL and DPR store at `$TMPDIR/faramesh/`
- Opens Unix socket at `/tmp/faramesh.sock`
- Starts accepting governance requests

### All Options

```bash
faramesh serve \
  --policy /etc/faramesh/payment.yaml \
  --data-dir /var/lib/faramesh \
  --socket /var/run/faramesh.sock \
  --slack-webhook https://hooks.slack.com/services/... \
  --log-level debug \
  --sync-horizon
```

**Options:**

| Flag | Description | Default |
|------|-------------|--------|
| `--policy` | Path to policy YAML file | `policy.yaml` |
| `--data-dir` | Directory for WAL and DPR SQLite | `$TMPDIR/faramesh` |
| `--socket` | Unix socket path | `/tmp/faramesh.sock` |
| `--slack-webhook` | Slack webhook URL for DEFER notifications | `""` |
| `--log-level` | Log level: `debug`, `info`, `warn`, `error` | `info` |
| `--sync-horizon` | Stream DPR records to Faramesh Horizon cloud | `false` |

## Unix Socket Connection

The daemon communicates via a Unix domain socket using newline-delimited JSON.

### Protocol

**Request format:**

```json
{
  "type": "govern",
  "call_id": "uuid-v4",
  "agent_id": "payment-bot",
  "session_id": "session-uuid",
  "tool_id": "stripe/refund",
  "args": {
    "amount": 100,
    "currency": "usd"
  }
}
```

**Response format:**

```json
{
  "effect": "PERMIT",
  "rule_id": "permit-low-value",
  "reason": "",
  "reason_code": "",
  "latency_ms": 8
}
```

**Effects:**

- `PERMIT` — Tool call allowed
- `DENY` — Tool call blocked
- `DEFER` — Tool call requires human approval
- `SHADOW` — Tool call allowed, decision logged but not enforced

### Manual Connection (Testing)

You can test the daemon with `nc` (netcat):

```bash
# Start daemon
faramesh serve --policy policy.yaml

# Connect with netcat
echo '{"type":"govern","call_id":"test","agent_id":"test","session_id":"test","tool_id":"stripe/refund","args":{"amount":100}}' | nc -U /tmp/faramesh.sock
```

**Response:**

```json
{"effect":"PERMIT","rule_id":"","reason":"","reason_code":"","latency_ms":5}
```

## Policy Loading

The daemon loads and compiles the policy file on startup.

### Policy File Format

```yaml policy.yaml
faramesh-version: '1.0'
agent-id: payment-bot
default_effect: permit

vars:
  max_refund: 500

rules:
  - id: deny-destructive-shell
    match:
      tool: shell/run
      when: 'args["cmd"] matches "rm\\s+-[rf]"'
    effect: deny
    reason: destructive shell command blocked by policy
    reason_code: DESTRUCTIVE_SHELL_COMMAND

  - id: defer-high-value-refund
    match:
      tool: stripe/refund
      when: 'args["amount"] > vars["max_refund"]'
    effect: defer
    reason: refund exceeds threshold — requires finance approval
    reason_code: HIGH_VALUE_REFUND
```

### Policy Compilation

On startup, the daemon:
1. Parses the YAML file
2. Validates rule structure
3. Compiles all `when` conditions to bytecode using [expr-lang](https://github.com/expr-lang/expr)
4. Computes policy version hash: `sha256:<first-16-chars>`

Compilation errors cause the daemon to exit with code 1.

### Policy Reloading

<Note>
The daemon watches the policy file for changes and automatically reloads. No restart required.
</Note>

**To force reload:**

```bash
touch policy.yaml
```

## WAL and DPR Store

The daemon maintains two persistent stores:

### Write-Ahead Log (WAL)

Every governance decision is written to the WAL **before** being returned to the caller. This is the ordering invariant:

```
CanonicalActionRequest
  │
  ├─[1-8]  Evaluation steps (kill switch, scanners, policy, etc.)
  ├─[9]    WAL write ──────────── fsync to disk BEFORE returning
  ├─[10]   Async replication to SQLite DPR
  └─[11]   Return Decision to caller
```

If step 9 fails → DENY. If the process crashes between steps 9 and 10, the WAL replays on restart. No gap in the audit chain is possible.

**WAL location:**

```
$TMPDIR/faramesh/wal/
  ├── 00001.wal
  ├── 00002.wal
  └── 00003.wal
```

### DPR (Decision-Provenance Record) Store

The DPR store is a SQLite database that contains the tamper-evident audit chain. Each record includes:

- `record_hash` — SHA256 of this record's canonical bytes
- `prev_record_hash` — SHA256 of the previous record (linked list)
- `policy_version` — Hash of the active policy at decision time
- `args_structural_sig` — Shape hash of arguments (never raw values)
- `effect` — PERMIT / DENY / DEFER / SHADOW

**DPR location:**

```
$TMPDIR/faramesh/faramesh.db
```

**Verify integrity:**

```bash
faramesh audit verify $TMPDIR/faramesh/faramesh.db
```

**Output:**

```
Verifying DPR chain integrity: /tmp/faramesh/faramesh.db
Records to verify: 1247

✓ Chain integrity verified. 1247 records, 0 violations.
```

## Running as a Service

### systemd (Linux)

```ini /etc/systemd/system/faramesh.service
[Unit]
Description=Faramesh Governance Daemon
After=network.target

[Service]
Type=simple
User=faramesh
Group=faramesh
ExecStart=/usr/local/bin/faramesh serve \
  --policy /etc/faramesh/policy.yaml \
  --data-dir /var/lib/faramesh \
  --socket /var/run/faramesh.sock \
  --log-level info
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

# Security hardening
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/faramesh /var/run

[Install]
WantedBy=multi-user.target
```

**Enable and start:**

```bash
sudo systemctl daemon-reload
sudo systemctl enable faramesh
sudo systemctl start faramesh
sudo systemctl status faramesh
```

**View logs:**

```bash
sudo journalctl -u faramesh -f
```

### launchd (macOS)

```xml ~/Library/LaunchAgents/dev.faramesh.daemon.plist
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>dev.faramesh.daemon</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/local/bin/faramesh</string>
        <string>serve</string>
        <string>--policy</string>
        <string>/Users/YOUR_USER/.faramesh/policy.yaml</string>
        <string>--data-dir</string>
        <string>/Users/YOUR_USER/.faramesh/data</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/Users/YOUR_USER/.faramesh/stdout.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/YOUR_USER/.faramesh/stderr.log</string>
</dict>
</plist>
```

**Enable and start:**

```bash
launchctl load ~/Library/LaunchAgents/dev.faramesh.daemon.plist
launchctl start dev.faramesh.daemon
launchctl list | grep faramesh
```

### Docker Compose

```yaml docker-compose.yml
version: '3.8'

services:
  faramesh:
    image: ghcr.io/faramesh/faramesh:latest
    command: serve --policy /policy/policy.yaml --socket /var/run/faramesh.sock
    volumes:
      - ./policy.yaml:/policy/policy.yaml:ro
      - faramesh-data:/var/lib/faramesh
      - faramesh-socket:/var/run
    restart: unless-stopped

  agent:
    image: my-agent:latest
    volumes:
      - faramesh-socket:/var/run
    environment:
      - FARAMESH_SOCKET=/var/run/faramesh.sock
    depends_on:
      - faramesh

volumes:
  faramesh-data:
  faramesh-socket:
```

**Start:**

```bash
docker-compose up -d
```

```
[10:15:27] DEFER   stripe_refund          payment-bot        rule=defer-high-value  latency=6ms
```

### Logs

The daemon outputs structured logs in JSON format (production) or human-readable (default).

**Set log level:**

```bash
faramesh serve --policy policy.yaml --log-level debug
```

**Log levels:**

- `debug` — Verbose debugging (policy evaluation, WAL writes)
- `info` — Normal operation (startup, policy reloads)
- `warn` — Warnings (policy validation issues)
- `error` — Errors (policy compilation failures, WAL errors)

### Health Check

Check if the daemon is running:

```bash
test -S /tmp/faramesh.sock && echo "Daemon running" || echo "Daemon not running"
```

**Programmatic health check:**

```python
import socket
import json

def is_daemon_running(socket_path="/tmp/faramesh.sock"):
    try:
        sock = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
        sock.settimeout(1)
        sock.connect(socket_path)
        sock.close()
        return True
    except:
        return False

print(is_daemon_running())  # True or False
```

## Performance

The daemon is designed for sub-millisecond latency:

- Policy evaluation: **~1μs per rule** (compiled bytecode)
- WAL write: **less than 1ms** (fsync to disk)
- Total latency: **less than 10ms** for typical policies (3-5 rules)

**Benchmark your policy:**

```bash
faramesh policy test policy.yaml --tool stripe/refund --args '{"amount":100}'
```

**Output:**

```
  Tool:    stripe/refund
  Effect:  PERMIT
  Rule:    permit-low-value
  Reason:  
  Code:    
  Latency: 5ms
```

## Troubleshooting

### Daemon won't start

**Error:**

```
Error: listen unix /tmp/faramesh.sock: bind: address already in use
```

**Solution:** Another daemon is running or stale socket exists.

```bash
rm /tmp/faramesh.sock
faramesh serve --policy policy.yaml
```

### Policy compilation fails

**Error:**

```
Error: compile policy: rule 'defer-high-value': when condition parse error: unexpected token
```

**Solution:** Fix the `when` expression in your policy.

```bash
faramesh policy validate policy.yaml
```

### WAL write errors

**Error:**

```
Error: WAL write failed: disk full
```

**Solution:** Free up disk space or change `--data-dir` to a different volume.

### Socket permission denied

**Error:**

```
Error: connect to daemon: permission denied
```

**Solution:** Ensure the socket has correct permissions or run as the same user.

```bash
chmod 666 /tmp/faramesh.sock
```

## Security Considerations

### Unix Socket Permissions

By default, the socket is created with permissions `0700` (owner only). To allow other users:

```bash
chmod 666 /tmp/faramesh.sock  # All users
chmod 660 /tmp/faramesh.sock  # Owner + group
```

### Policy File Access

The policy file should be read-only to the daemon user:

```bash
chown root:faramesh /etc/faramesh/policy.yaml
chmod 640 /etc/faramesh/policy.yaml
```

### Data Directory Isolation

The data directory contains the WAL and DPR store. Restrict access:

```bash
chown -R faramesh:faramesh /var/lib/faramesh
chmod 700 /var/lib/faramesh
```
